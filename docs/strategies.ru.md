# Стратегии

Каждая стратегия реализует `Strategy` из `core.strategies.base`. Стратегия
получает `NormalizedPrompt` и целевой `ModelProfile`, затем возвращает
`CandidatePrompt`, который валидатор и scorer сравнивают с другими кандидатами.

## Role-based

Добавляет явную экспертную роль под обнаруженный тип задачи. Стратегия
применима всегда и достаточно дешевая для небольших локальных моделей.

## Structured output

Добавляет контракт вывода: JSON для extraction или classification, fenced code
blocks для code generation, списки для summaries и plain text для translation.
Это уменьшает неоднозначность постобработки.

## Chain decomposition

Использует структуру restate, plan, execute для задач с рассуждением, например
`reasoning`, `code_generate` и `extract`. Пропускается для профилей с
`reasoning_mode = thinking`, потому что такие модели уже делают внутреннюю
декомпозицию.

## Few-shot

Добавляет один или два компактных task-specific примера, если хватает
оставшегося контекстного бюджета. Примеры выбираются по категории задачи и не
должны вытеснять пользовательский запрос.

## Self-verification

Добавляет цикл самопроверки: перечитать запрос, перечислить пропущенные
ограничения и пересмотреть ответ. Полезно, когда `max_output_tokens >= 256`.

## Multimodal

Запускается только когда выбранный профиль имеет `supports_vision: true`, а
промпт содержит вложения. Кандидат называет каждое вложение и просит модель
описать наблюдения перед ответом.

## Выбор

`core.strategy_selector.select` фильтрует стратегии через `applies()` и
упорядочивает их по приоритету. Таблица приоритета зависит от задачи: для
задач с интенсивным рассуждением (`reasoning`, `code_generate`, `extract`)
chain decomposition и self-verification поднимаются выше общих ролевых и
форматных стратегий; для остальных задач порядок по умолчанию. Порядок остаётся
детерминированным. Orchestrator валидирует каждого кандидата, вычисляет
интегральную оценку `S` и возвращает редакцию с максимальным результатом.
