# Интегральная оценка качества

Каждый candidate prompt оценивается по пяти нормализованным метрикам в
$[0, 1]$. Финальная оценка — взвешенная сумма:

$$
S = 0.30\,q_c + 0.25\,q_p + 0.20\,q_s + 0.15\,q_t + 0.10\,q_l
$$

Вектор весов по умолчанию:
$\mathbf{w} = (0.30, 0.25, 0.20, 0.15, 0.10)$, где $\sum w_i = 1$.

| Символ | Метрика | Что отражает |
| --- | --- | --- |
| $q_c$ | Clarity | Структура, однозначность формулировки, явная роль и формат вывода. |
| $q_p$ | Prompt compliance | Покрытие намерения пользователя и ограничений. |
| $q_s$ | Safety | Отсутствие запрещенного контента и наличие safety guards. |
| $q_t$ | Token cost | Обратная стоимость токенов относительно бюджета модели. |
| $q_l$ | Latency | Обратная оценка задержки относительно настроенного SLO. |

Компонент token cost нормализуется по контекстному окну активного профиля $C$:

$$
q_t = 1 - \min\!\left(\frac{n_{\text{tokens}}}{C},\; 1\right)
$$

Компонент latency нормализуется по целевому SLO $T$:

$$
q_l = \mathrm{clip}_{[0,1]}\!\left(\frac{T}{p_{50}}\right)
$$

где $p_{50}$ — измеренная медианная задержка профиля.

## Пользовательские веса

Веса настраиваются по режимам deployment: `production`, `research` и `eval`.
`core.evaluator.IntegratedScorer` повторно нормализует любой пользовательский
вектор $\mathbf{w}'$ так, чтобы $\sum w'_i = 1$, и только затем применяет
формулу. Сырые значения метрик за пределами $[0, 1]$ обрезаются перед оценкой.

## Веса с учётом профиля и задачи

Когда включён `IntegratedScorer.profile_aware` (по умолчанию),
`core.evaluator.resolve_weights` корректирует базовый вектор для каждой оценки
перед повторной нормализацией:

- **Локальные профили** (`gguf`/`safetensors`) повышают веса token-cost и latency
  в $1.5\times$, так как модели на устройстве ограничены контекстом и медленнее.
- **Задачи с интенсивным рассуждением** (`reasoning`, `code_generate`, `extract`)
  повышают веса clarity и prompt-compliance в $1.3\times$.

Корректировки складываются, а результат повторно нормализуется к $\sum w_i = 1$,
поэтому оценка остаётся в $[0, 1]$. Передайте `profile_aware=False`, чтобы
использовать фиксированный вектор. `scripts/benchmark.py` печатает дельту оценки
по задачам между двумя режимами.

## Подсчёт токенов

Терм token-cost опирается на `core.tokenizer.count_tokens`. С установленной
группой `ml` используется настоящий BPE-токенизатор (tiktoken, `cl100k_base`);
иначе применяется эвристика `~4 символа на токен`. Любая ошибка токенизатора
тоже приводит к эвристике, поэтому запуски без зависимостей детерминированы.

## Сохранение исходного намерения

Когда настроен backend `SemanticSimilarity` (`PAI_SCORER__SEMANTIC=1`, который
загружает `EmbeddingSimilarity` из группы `ml`), терм prompt-compliance
смешивается с косинусной близостью между кандидатом и исходным запросом:

$$
q_p = (1 - \beta)\, q_p^{\text{heuristic}} + \beta \cdot \mathrm{sim}(\text{candidate}, \text{original})
$$

где $\beta$ = `PAI_SCORER__SEMANTIC_BLEND` (по умолчанию $0.5$). Это не даёт
кандидату победить за счёт набивки маркерных слов при потере реального запроса
пользователя. Сигнал опционален и безопасно деградирует: без backend, без
ссылки или при любой ошибке эмбеддинга $q_p$ остаётся чистой эвристикой.

## Воспроизводимость

Каждая оценка сохраняет:

- id candidate prompt,
- resolved `ModelProfile`,
- сырые значения $q_i^{\text{raw}}$ и нормализованные значения $q_i$ по метрикам,
- интегральную оценку $S$,
- человекочитаемое объяснение.

Решение можно восстановить через `GET /v1/history/{session_ref}`.
