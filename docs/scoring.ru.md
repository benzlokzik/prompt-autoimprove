# Интегральная оценка качества

Каждый candidate prompt оценивается по пяти нормализованным метрикам в
$[0, 1]$. Финальная оценка — взвешенная сумма:

$$
S = 0.30\,q_c + 0.25\,q_p + 0.20\,q_s + 0.15\,q_t + 0.10\,q_l
$$

Вектор весов по умолчанию:
$\mathbf{w} = (0.30, 0.25, 0.20, 0.15, 0.10)$, где $\sum w_i = 1$.

| Символ | Метрика | Что отражает |
| --- | --- | --- |
| $q_c$ | Clarity | Структура, однозначность формулировки, явная роль и формат вывода. |
| $q_p$ | Prompt compliance | Покрытие намерения пользователя и ограничений. |
| $q_s$ | Safety | Отсутствие запрещенного контента и наличие safety guards. |
| $q_t$ | Token cost | Обратная стоимость токенов относительно бюджета модели. |
| $q_l$ | Latency | Обратная оценка задержки относительно настроенного SLO. |

Компонент token cost нормализуется по контекстному окну активного профиля $C$:

$$
q_t = 1 - \min\!\left(\frac{n_{\text{tokens}}}{C},\; 1\right)
$$

Компонент latency нормализуется по целевому SLO $T$:

$$
q_l = \mathrm{clip}_{[0,1]}\!\left(\frac{T}{p_{50}}\right)
$$

где $p_{50}$ — измеренная медианная задержка профиля.

## Пользовательские веса

Веса настраиваются по режимам deployment: `production`, `research` и `eval`.
`core.evaluator.IntegratedScorer` повторно нормализует любой пользовательский
вектор $\mathbf{w}'$ так, чтобы $\sum w'_i = 1$, и только затем применяет
формулу. Сырые значения метрик за пределами $[0, 1]$ обрезаются перед оценкой.

## Воспроизводимость

Каждая оценка сохраняет:

- id candidate prompt,
- resolved `ModelProfile`,
- сырые значения $q_i^{\text{raw}}$ и нормализованные значения $q_i$ по метрикам,
- интегральную оценку $S$,
- человекочитаемое объяснение.

Решение можно восстановить через `GET /v1/history/{session_ref}`.
